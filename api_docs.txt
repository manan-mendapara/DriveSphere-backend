## Authentication & Error Handling

### Authentication
- All protected endpoints require a valid JWT token in the `Authorization: Bearer <token>` header
- Token is verified by `authMiddleware` which attaches user data to `req.user`
- Admin endpoints additionally check `req.user.role === "admin"` via `adminMiddleware`

### Common Error Responses
- `400 Bad Request`: Invalid request data, missing parameters, or validation failures
- `401 Unauthorized`: Missing or invalid authentication token
- `403 Forbidden`: Authenticated but insufficient permissions (non-admin trying admin endpoints)
- `404 Not Found`: Requested resource doesn't exist
- `409 Conflict`: Resource already exists (e.g., duplicate email)
- `422 Unprocessable Entity`: Validation failed on semantically correct data
- `500 Internal Server Error`: Unexpected server error

### Success Response Format
Most endpoints use the `sendResponse` helper which returns:
```json
{
  "success": boolean,
  "message": string,
  "data": any,          // For single items or arrays
  "count": number       // Only present for list endpoints that return arrays
}
```

List endpoints that return arrays include both `data` (the array) and `count` (array length) in their response. Single item endpoints only include `data`.
